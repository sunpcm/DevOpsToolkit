## 环境与复现

控制端为 macOS，使用既有的 Python 3.14.6、隔离 `ansible-core==2.21.4` 和三项
`ansible/collections.lock.json` 锁定的 collections；验收前重新运行
`scripts/verify-collection-lock.py` 校验 requirements 与已安装版本，没有在宿主机安装软件。
先在该 SHA 执行 `./tests/verify-ansible.sh`，退出码 0；远端该合并提交的
quality、Python 3.12/3.14 检查也全部成功。

一次性验收命令（`PATH` 与 `ANSIBLE_COLLECTIONS_PATH` 分别指向已校验的隔离运行时与 collections）：

```bash
./tests/multipass-smoke.sh run --with-faults --report <受控目录>/vm-report-9d613e8.txt
python3 scripts/verify-vm-evidence.py verify-report \
  --report <受控目录>/vm-report-9d613e8.txt \
  --sha 9d613e85b4adaae4c9c8a5a7231556d68960b07e
shasum -a 256 <受控目录>/vm-report-9d613e8.txt
```

原始机器可读报告见同目录的
[`2026-09-24-release-vm-9d613e8.report`](2026-09-24-release-vm-9d613e8.report)，
SHA256 为 `8d532fcb537c2e1db05332db08d0b364fb1362691b7832de283043bd5737565a`。

`cleanup_status=passed`、Ubuntu 22.04/24.04 两个不同实例及实际镜像版本。

  `ok=69 changed=0 unreachable=0 failed=0`；SSH/UFW/Docker/Nginx 检查通过。

  `ok=71 changed=0 unreachable=0 failed=0`；服务检查通过。
