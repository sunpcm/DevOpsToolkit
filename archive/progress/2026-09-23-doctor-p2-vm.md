`7b1ca5c` 已修复传参，并新增命令断言。修复后 `./tests/verify-ansible.sh` 与
`python3 tests/test-doctor.py` 均通过。此前仅本地模拟的报告不能作为远端验收证据。

| 未知主机密钥 | 同一实现与单元测试覆盖，未在此 VM 单独复跑 | 拒绝，退出码 1；空 `known_hosts` 未被写入 |

每台 VM 的 SSH ED25519 指纹先经 `multipass exec` 从 `/etc/ssh/ssh_host_ed25519_key.pub`
读取，再与 `ssh-keyscan` 的指纹比较一致，之后才把公钥写入仅限本次测试的 `0600`
`known_hosts`。只向一次性 VM 的 `ubuntu`/`root` 账户添加临时测试公钥；没有关闭
`StrictHostKeyChecking`、使用 `accept-new` 或复用旧 SSH ControlMaster。

控制端与目标端的网络结果仅为 TCP/443 可达性，不等于 TLS、代理、Docker GPG 或
Release 下载可用。22.04 的一轮控制端 GitHub TCP 超时被正确标为 warning，目标端两项通过。
`--no-network` 的结果也正确标为 warning；没有把跳过项计为通过。
